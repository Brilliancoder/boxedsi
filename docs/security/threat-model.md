# Threat model

Assets: originals on the device, the placeholder map, the journal's integrity, and the trust of the employer's security team.

Trust boundary: everything on the employee's computer under the employee's account is trusted; the AI service and the content it returns are not; an AI agent running on the computer is treated as untrusted code with the employee's rights.

| Threat | What boxed does | What remains |
|---|---|---|
| A detector misses sensitive data | Rules with checksums, project dictionaries, optional local NER, a benchmark per release, preview before sending | Misses are possible; the benchmark publishes the rate |
| Re-identification from context | Levels: at higher levels numbers and rare facts are hidden too; level 4 sends only the task and the table schema | Placeholders hide direct identifiers, not context |
| An agent reads originals with its file tools | Masked copy of the project; deny rules for the original and for boxed data; hooks on every file tool | - |
| An agent reaches originals through the shell or a search from a parent folder | The hook blocks paths into or above protected folders after normalising quotes, escapes, globs and braces; the macOS sandbox denies the original at OS level | Without the sandbox the hook is best effort: paths and names built at run time, a bare `~` or `/` inside a nested shell string (`bash -c 'ls ~'`), a `cd` that is not followed by `&&` on the same line, and arithmetic the hook cannot compute can still reach outside. A differential against real bash and zsh (about 400k generated commands, 2026-10-24) found no harmful allowance |
| An agent under `boxed run` starts a process outside the sandbox or changes what runs later | The profile denies LaunchServices opens, Apple Events, preference writes, terminal and window-server input injection, login items, Shortcuts and authorization services, and writes to the agents' instruction and settings files, `~/.local` and `~/.cache`; hooks run with `python -I`; locks time out and fail closed | Not yet denied: the clipboard, sockets of IDEs, tmux and the person's ssh-agent, `~/Library/Caches`; MCP tools do not work inside `boxed run` until a broker outside the sandbox holds the vault |
| An agent under `boxed run`, or a process it starts, reads credentials from its environment | `boxed run` takes out of the agent's environment every variable whose name has a word of credentials in it (`KEY`, `TOKEN`, `SECRET`, `PASSWORD`, `AUTH` and the like, also fused as in `PGPASSWORD`, `MYSQL_PWD`, `NPM_TOKEN`; `SSH_AUTH_SOCK`, `SSHPASS`, `BW_SESSION` and `*_DSN` included) or whose value the detectors read as a secret, a private key or a JWT, and names them (names only) in one line before the start | The agent's own sign-in variables, the proxy variables (a proxy address may hold a password) and what `--keep-env` names pass, and the agent and every process it starts can read them. Files are not the environment: `~/.aws`, `~/.netrc` and the like stay readable, and so does the ssh-agent socket itself for a process that finds its path |
| An agent runs boxed itself to learn values (restore, or masking guesses to compare placeholders) | Every boxed command is blocked inside a masked copy | Without the sandbox the block is the hook's, with the same best-effort limits as above |
| A guard hook crashes or times out | Hooks are configured to block the call on failure (Claude Code 2.1.295 or later) | Older clients are not supported for masked copies |
| A model invents or breaks placeholders | Restore never guesses: unknown and half-broken placeholders are reported and sync refuses the file | - |
| Theft of the placeholder map | AES-256-GCM, key in the OS keychain; the vault never leaves the device | Malware running as the employee can ask the keychain |
| Changing or deleting journal records | Hash chain with Ed25519 signatures; verify reports damaged lines, an edited record, a record removed, added or moved before the last one, and a wrong key | Records cut off the end, or a journal removed whole, still verify: the chain that is left is whole. Only a record count or a last hash kept elsewhere (an earlier export) shows that cut. The journal proves what was recorded, not that nothing was sent around boxed |
| Scripts on an AI website read restored text | Restore happens only in the boxed side panel or app, never on the provider's page | - |
| A poisoned dependency or update | Pinned dependencies, open source, reproducible builds planned | - |
| Instructions hidden in AI answers | Answers are data; a level 4 plan is a strict JSON grammar run by a local executor, never code | - |
| An API error or answer echoes the prompt or the key | An error names the provider, the HTTP status and a word from a fixed list; a body is never quoted, logged or journaled. A redirect is never followed, so the key header stays with the address the employee named | - |
| An answer asks for the placeholders of earlier prompts, to print an earlier secret | An answer gets back only the placeholders of its own prompt | - |
| The API address is changed, so a relay receives the key | The address comes only from `BOXED_<PROVIDER>_BASE_URL`; it must be https, or http to the same computer, with no login in it; the journal marks such sends `relay` | A relay the employee names sees the masked prompt and the key |
| A request goes out before it is recorded, or against the policy | The policy is decided first, the `sent` record is written before the request, and a record that cannot be written stops the request | - |
| Observation mode reads what the employee sends | Off until switched on; the extension never blocks or changes a send; only kinds, counts and a keyed hash are kept, never the text; the log is a chain of its own and is not in the export | WebSocket messages and attachments are not checked; the log shows what the extension read, not everything that was sent |
| A training setting is stale, unknown or the file is damaged | A check shows a due mark after 30 days or while a field is unknown (when the panel or `boxed check list` is opened). `boxed check list` also shows the recipient kind each account counts as: only "off" is `personal-private`; "on", unknown, a missing check and a damaged `checks.json` give the stricter `personal-training`. A damaged file is moved aside, not deleted | Nothing applies that kind by itself yet: `boxed ask` and `boxed policy check` use the kind the employee passes (`--account`, `--recipient`), so it has to be copied from the list. `checks.json` is the employee's word, signed with the device key: an edited or foreign file reads as "confirm again", but a process running as the employee can still put back an older signed copy. boxed does not read the provider's settings page |
| A file holds data in a place the clean copy is not built from | The copy holds only what was read; what was left out is named, and "complete: no" says so | Content that no reader of the format sees |
| A huge table exhausts time or memory | `boxed plan` refuses a table of more than 5,000,000 cells | - |
| An answer carries terminal control sequences (cursor moves, a window title, OSC 52 writes to the clipboard) | On a terminal `boxed ask` shows control characters other than the line feed and the tab as `\xNN`; into a pipe or a file the answer is exact | A program that reads the file or the pipe |
| A report is written over the journal, the vault or a keys file | `boxed dashboard` writes no file in the boxed home except under `reports/`, only a new file or a report of its own, never the same file twice, through a part file and a rename | - |
| A proxy from the environment sees the key and the prompt of a relay on this computer | An address on this computer is never handed to a proxy | A remote relay follows `HTTPS_PROXY` and sees what that proxy sees |
| A level 4 request is sent as a masked prompt | `boxed ask` refuses level 4 and a policy that needs it; no record of `boxed ask` says more than level 3 | - |
| A skill, plugin, MCP server or hook of an agent is malicious (steals keys, runs a downloaded program, redirects the API address, hides orders for the model) | `boxed skills scan` reads every place where the agents on the computer load extensions, and a folder or address before install, and rates each item `dangerous`, `suspicious` or `ok` with the reason, the file and the line. Rules cover 22 classes of known techniques. Files are read whole, base64 and invisible Unicode text are decoded, and what cannot be read (programs, archives, links out of the item) is a finding, and so is a check that stopped at one of its limits (`incomplete`). Nothing is run, and no link inside an item is followed; the config files of the agents themselves (`~/.claude/settings.json`, a project's `.claude/settings.json` and the like) are read where they point when they are links, as the agent reads them | Static rules read patterns, not meaning: instructions in plain language and new techniques can pass. MCP servers are not started, so what they tell the model at run time is not checked. `ok` is not a guarantee, and a scan is a moment. Known gaps are listed below |
| A scanned file tries to talk the check into a pass, or to hurt the reader (a note to the reviewer, text that imitates the markers of the AI check, terminal codes or markup in a name or a line) | Text addressed to a reviewer is a `high` finding by itself. With `--ai` the model can only add findings: nothing in its answer removes or lowers one, a finding needs a quote that occurs in the file, the text sits between markers derived from its own hash, and the answer is parsed as strict JSON. Text from files is cleaned before it reaches a terminal; the HTML report escapes everything and has no script, link or resource from outside; the JSON is plain ASCII | A model can still be misled into adding nothing, so "no AI findings" is not a clean bill. A report names real folders and extensions: read it before you share it |
| A hostile folder, zip or repository harms the computer when it is checked (links to files elsewhere, archives that unpack outside their folder or without end, git hooks) | No link is followed; files and unpacked bytes are capped (10,000 files, 256 MiB); zip members that leave their folder or repeat are refused and links in an archive are not made; a repository is cloned over https only, to depth 1, without submodules, LFS, hooks or git configuration, within 120 seconds, into a private temporary folder that is removed afterwards | The `git` program and the git host are trusted as far as they are in any clone |
| A dangerous extension is installed, or one changes, and the employee does not notice | boxed keeps the record of the last check (a digest for each item). At the start of a Claude Code session the plugin's hook says what is new or changed since, and what was found dangerous and is still installed. The model gets a fixed note with opaque references (a hash of each id, no name or folder, which are the attacker's text) and is told to ask the person before it uses an extension. It only informs: it blocks and quarantines nothing and uses no network, and its failure never disturbs a session | It sees Claude Code, the user level and the current folder, after a first scan; it is silent where `boxed` is not found and under `boxed run`. Codex has no warning, and boxed hooks do not run on Windows. A change between two starts is seen at the next start |
| Quarantine loses or damages something, or happens without the employee | Only the employee's command quarantines. Each kind of item has a way back: a move to a private folder of boxed, a switch (`enabledPlugins`, `enabled = false`, `disabledMcpjsonServers`), or an entry cut out and saved first. A config file is edited only after it parses, is rewritten through a part file and is read again just before; a restore writes the old bytes back when nobody touched the file, otherwise puts the entry back, checked by parsing. A link, a file that does not parse or a file that changed under the edit is refused | The quarantine folder `skills/quarantine/<id>/` (0700, files 600) keeps what was cut out in `entry.json`, which can include `env` and header values, and, for every config file boxed edited, `original`: a full copy of that file as it was before the edit, so it also holds the values of the other entries in it (other servers' `env` and headers, allowed commands). Both stay as exposed as the original config until `restore`, which takes them away; deleting the boxed folder deletes them. Quarantine stops an item from loading; it does not undo what the item already did |
| The record of checks is forged or replaced, to hide a warning | The record is read strictly (a file that is not exactly what boxed writes is an error), has mode 600 in a private folder, and an agent in a masked workspace or under `boxed run` cannot read or write `skills/`. Scans of what is installed, quarantines and restores are in the signed journal, channel `skills` | The record is not signed on purpose: a program running as the employee can rewrite it, which hides a warning or marks an item as checked. That program could switch the hook off as well |
| A secret in an extension's config leaks through a report, the record, the journal or a request to a model | A value from `env`, headers or a command is never printed, stored in the record or journaled. Evidence has secrets and personal data replaced by `[KIND]`, found in the text around an excerpt before it is cut, before it reaches a terminal, a report or a prompt; the record keeps no evidence, of a model's finding only its rule, severity, file and line. With `--ai` no config entry and no config file of an agent (settings, MCP, hooks and Codex config files, plugin manifests) is sent, and the files that are sent are masked, pass the policy and are journaled like any `boxed ask` | `entry.json` of a quarantine keeps the cut entry whole and `original` the whole edited file (mode 600). Host names, URLs and, in a report, IP addresses stay readable because they are the evidence. `--ai` sends the masked text of files that already have findings to the provider the employee names |

Known limits, also listed in the product README: the agent can read the masked copy's settings file, which names the original project folder (not its content); `boxed run codex` turns Codex's own sandbox off because macOS cannot nest sandboxes, so the boxed sandbox is the outer guard; Linux agents are not sandboxed yet; on Windows 11 the core commands and the native host of the browser extension run, while `boxed run`, `boxed workspace`, the Claude Code hooks, `boxed mcp` and `boxed install claude` and `codex` refuse to start there, and `boxed skills` has not been tried on a Windows computer (see [windows.md](../guide/windows.md)).

## Known gaps of the extension check

`boxed skills scan` is a heuristic built on static rules, not a guarantee. A verdict of `ok` means that no rule matched, not that the item is safe. In the current version these classes of technique are known to pass the check, or to weaken it:

- Download and run split over several steps or lines. A download saved to a file and run by a later command, or code fetched on one line and executed a few lines further down, can carry no finding, while the same thing written as one pipe or one call is flagged.
- Import aliases and indirect calls. The rules look for well-known names and call shapes; a module imported under another name, or a call made through a variable, can pass.
- Scripts the inventory does not count as part of an item. A hook that runs a script through an interpreter is judged together with that script only when the inventory resolves the path to it. A script without a file extension, or one reached through a link and a relative path with `..` steps, can stay outside the hook, which is then rated by its command line alone.
- Content hidden in files that are not text, and in config keys the inventory does not read. Text inside images and other media is not checked as a script is. Installed agent configs are checked entry by entry, so a key that is not one of the known entries (for example free-form instructions in a Codex config) is not read as text; the same config given as a target folder is.
- Denial of service on very large input. A repository given as a target is cloned within a time limit (120 seconds) but without a size limit, and every file is read whole. A very large repository, archive or media file can make a scan slow, or fill the disk of the temporary folder before the time limit stops it.
- `--ai` sends the files of different items in one request. Files with findings are grouped into requests of up to 100 KiB whichever item they belong to, so a hostile file can influence how the model judges the files of another item in the same request, and a failed request stops the requests after it.

What to do about it:

- Read the code of an extension before you install it, its scripts and hooks first. Treat `ok` as "no known pattern found", and a scan as one moment.
- Quarantine an item you cannot explain (`boxed skills quarantine`); `boxed skills restore` puts it back.
- Run coding agents under the macOS sandbox (`boxed run`), so that an extension that passed the check still cannot read the original project or the sensitive parts of the boxed home, or write the agents' instruction and settings files.
